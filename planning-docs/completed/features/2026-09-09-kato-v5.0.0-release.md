# Milestone: KATO v5.0.0 Release (MAJOR)

**Completed**: 2026-09-09
**Type**: Release / Milestone (major version bump)
**Impact**: First major release since 4.0.0; ships a breaking prediction-field change and a batch of accumulated fixes/features from the same day's work
**Decision**: DECISION-022 in `planning-docs/DECISIONS.md` (resolves DECISION-019's open version-bump question)

## Summary

KATO v5.0.0 was released via `./container-manager.sh major "..."` (AUTO_MODE), bumping from 4.x to 5.0.0. The major bump was required because DECISION-019 (same day) redefined the `anomalies` prediction field and split its former fuzzy-match detail into a new `fuzzy_matches` field — a breaking change for any consumer reading fuzzy detail from `anomalies`. That single breaking change set the bump level; everything else in the release is additive or a non-breaking fix.

## Process Notes (for next release — see also DECISION-022 and `project-manager/maintenance-log.md`)

1. **Verify registry auth before running `container-manager.sh`.** The shell's `GITHUB_PERSONAL_ACCESS_TOKEN` was an expired token (GitHub API 401); the keychain's cached `ghcr.io` credential was also dead (403 on push). Fix: `source ~/.bash_profile` to pick up the current PAT (needs `write:packages` scope), then `docker login ghcr.io -u sevakavakians --password-stdin`.
2. **The script's operation order is tag/release first, image build second.** `container-manager.sh` does not perform its own registry login and pushes the tag + publishes the GitHub release *before* building and pushing the image. If registry auth is bad, a failed image push leaves a tagged, released version with no matching image on `ghcr.io` — verify auth first, don't rely on the script to fail safe.
3. **Stash uncommitted WIP before bumping.** `git stash push -u` held out the metadata-sidecar planning file's uncommitted follow-up work for the release, restored right after. Repeat this pattern for any future release with in-flight uncommitted work that shouldn't ship.
