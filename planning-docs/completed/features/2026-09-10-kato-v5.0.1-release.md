# Milestone: KATO v5.0.1 Release (PATCH)

**Completed**: 2026-09-10
**Type**: Release / Milestone (patch version bump)
**Impact**: Ships the previously-documented-but-uncommitted DECISION-018 metadata-sidecar round-trip fix plus reference Python client bug fixes; no API change
**Decision**: DECISION-023 in `planning-docs/DECISIONS.md`

## Summary

KATO v5.0.1 was released via `./container-manager.sh patch "..."` (AUTO_MODE), bumping from 5.0.0 to 5.0.1. The patch bump reflects that neither piece of work in this release changes any API contract: the DECISION-018 metadata-sidecar fix is a behavior-preserving round-trip elimination (2 ClickHouse SELECTs → 1 per re-learn, same externally-observable result), and the reference Python client fixes touch only `examples/`, not `kato/` service code.

The notable wrinkle: the DECISION-018 fix had already been logged **COMPLETE** on 2026-09-09 and listed in v5.0.0's "What's Bundled" table, but the actual code change was never committed — it remained uncommitted working-tree WIP (`M kato/informatics/knowledge_base.py`, `M kato/storage/metadata_router.py`) straight through the v5.0.0 release and was still sitting there a day later. This release corrects that: the fix is now genuinely committed and shipped.

## Process Notes (for next release — see also DECISION-023 and `project-manager/patterns.md`)

1. **`set -e` + `source ~/.bash_profile` in a non-interactive shell can abort before any state changes.** The first release attempt exited immediately because `source ~/.bash_profile` returned non-zero in the non-interactive release shell and the wrapper used `set -e`. Nothing had been bumped or tagged, so it was a harmless abort. Fix: `source ~/.bash_profile || true` when the goal is only to refresh environment variables. Recorded alongside the 2026-09-09 stale-credential process note in `planning-docs/project-manager/patterns.md`.
2. **Verify the working tree against planning-doc "COMPLETE" claims before assuming a release is comprehensive.** DECISION-018 was marked COMPLETE and even listed in v5.0.0's "What's Bundled" table, but the code was never actually committed — it was live uncommitted WIP the whole time. A `git status`/`git diff` check against what the docs claim is shipped, done either right before or right after a release, would have caught this a day earlier.
