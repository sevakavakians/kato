# KATO v7.1.0 release (MINOR): `ends_here`
*Completed 2026-11-16*

## Change (PR #23, branch `feat/ends-here-share`, merged to main as `8422680`; feature commit `d11f86a`, docs `690c28e` and `206c7ed`)
- `future_potentials` used to share the probability among the candidates that have a future. Every candidate now takes its share of e^potential. A candidate with a future gives its share to its next event; a candidate whose pattern has ended gives it to `ends_here`, a new response field beside `chance_posterior` (`null` when there is no candidate). The probabilities and `ends_here` add up to 1. `predictive_information` uses the same shares. Requests in which no candidate has ended return the 7.0.0 values, with `ends_here` 0.0. Code: `_next_events` and new `ends_here()` in `kato/informatics/prediction_metrics.py`.
- User decisions, 16 Nov 2026: (1) rescale `future_potentials` so that a pattern that has ended keeps its share, returned as `ends_here`, chosen over returning `ends_here` beside an unchanged `future_potentials`. (2) The release is a MINOR bump (adds a response field; requests where no candidate has ended return what 7.0.0 returned). (3) The running instance and its databases are cleared before the gate, with no backup, and 7.1.0 is deployed on the empty store. The decision was made in another Claude session without Docker or planning-docs access; this session executed it.
- Why: with ended patterns left out, a poor match could be given 1.0. A node that learned `a b c` and `a b d` and observed `a`,`b`,`c` returned `d` at 1.0, although the pattern proposing `d` explained the observation worse than chance. It now returns `d` at 0.0004 and `ends_here` at 0.9996. The denominator over every candidate is also the one the weights of `potential` were fitted under.
- Evidence: 58,600 held-out queries, each followed by an event; tables in `docs/reference/prediction-object.md` under "How Sure: `future_potentials`" and "How Sure: `ends_here`". `ends_here` averages 0.046 and is above 0.5 for 0.6% of queries (mean of four kinds of data); the top entry of `future_potentials` is unchanged and right as often (0.648); its stated probability averages 0.593 (was 0.616); as a ranking key `predictive_information` moves 0.617 -> 0.616.
- Closes the open follow-up recorded with 7.0.0 (SPRINT_BACKLOG item 14): `future_potentials` has no "ends here" share.
- Pre-merge verification (other session): CI on `8422680` green: ruff, bandit, pip-audit, `tests/tests/unit/` (823 passed against real ClickHouse, Redis, Qdrant).
